# Мини-конструктор сайтов (travelline.tech)

Веб-приложение для управления содержимым главной страницы-клона портала travelline.tech.
Публичная страница берёт данные из API, а через админ-панель редактируются её блоки:
тексты, карточки, порядок элементов. Изменения в админке сразу видны на публичной странице.

Учебный проект: летняя практика, разработка мини-конструктора сайтов.

## Стек

- Backend: C# / ASP.NET Core (.NET 10)
- База данных: PostgreSQL (через EF Core), схема — реляционные таблицы + jsonb
- Frontend: чистые HTML / CSS / JavaScript, без фреймворков
- Тесты: xUnit
- Инфраструктура: Docker + docker-compose

## Требования

- Для запуска в контейнерах: Docker и Docker Compose
- Для локального запуска: .NET 10 SDK и PostgreSQL 16

## Быстрый запуск (Docker)

1. Рядом с `docker-compose.yml` создать файл `.env` и задать пароль админа:

   ```
   ADMIN_PASSWORD=ваш_пароль
   ```

2. Запустить:

   ```
   docker-compose up --build
   ```

3. Открыть в браузере:
   - публичная страница — `http://localhost:5272`
   - админка — `http://localhost:5272/admin.html`
   - вход в админку: логин `admin`, пароль — значение `ADMIN_PASSWORD`

Миграции применяются автоматически при старте. Если база пустая, данные подтягиваются
из `SiteConstructor/data.json`. Данные PostgreSQL хранятся в томе `pgdata` и переживают
пересоздание контейнера.

## Локальный запуск (без Docker)

1. Поднять PostgreSQL и создать базу `siteconstructor` (или поправить строку подключения
   `ConnectionStrings:Default` в `SiteConstructor/appsettings.json`).

2. Задать пароль админа (в git не попадает):

   ```
   cd SiteConstructor
   dotnet user-secrets set "Admin:Password" "ваш_пароль"
   ```

   Логин по умолчанию — `admin`.

3. Запустить:

   ```
   dotnet run --project SiteConstructor
   ```

4. Открыть `http://localhost:5272`.

## Конфигурация

Настройки берутся из `appsettings.json` и переопределяются переменными окружения
(двойное подчёркивание — вложенность):

- `ConnectionStrings__Default` — строка подключения к PostgreSQL
- `Admin__Username` — логин админа (по умолчанию `admin`)
- `Admin__Password` — пароль админа (обязателен; в репозитории не хранится)

## Структура

```
SiteConstructor/
  Controllers/    HTTP-эндпоинты (тонкие: приём запроса → сервис → статус)
  Services/       бизнес-логика (валидация, Id, сортировка)
  Data/           интерфейсы хранилищ (IDataStore, ISubmissionStore) и реализации,
                  AppDbContext
  Models/         модели данных
  Migrations/     миграции EF Core
  wwwroot/        публичная страница, админка, стили, скрипты, шрифты, медиа
  data.json       начальные данные для сидинга пустой базы
SiteConstructor.Tests/   xUnit-тесты (изоляция от БД через Fake-хранилища)
Dockerfile               многостадийная сборка образа
docker-compose.yml       приложение + PostgreSQL
```

Архитектура слоёв: `Controller → Service → IDataStore`. Сервисы зависят от интерфейса
хранилища, а не от конкретной реализации, поэтому смена хранилища не затрагивает
бизнес-логику и тесты.

## API

Базовый префикс — `/api`.

- `GET  /api/content` — весь контент (открыто)
- `PUT/POST/DELETE /api/content/...` — управление блоками (требует авторизации)
- `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me` — вход, выход, сессия
- `POST /api/submissions` — приём заявки с публичной формы (открыто)
- `GET /api/submissions`, `DELETE /api/submissions/{id}` — просмотр и удаление заявок (требует авторизации)

Чтение контента открыто, операции записи закрыты cookie-авторизацией.

## Ограничения (учебный проект)

- Пароль админа сравнивается в открытом виде. В продакшене хранился бы хеш
  (bcrypt/PBKDF2) и добавлялась бы CSRF-защита.
- Поля заявок в инбоксе рендерятся во `innerHTML` без экранирования — потенциальная
  поверхность для stored-XSS; поля нужно экранировать перед вставкой.
- Запись контента идёт через replace-all в транзакции — приемлемо для текущих объёмов,
  при росте данных заменяется на точечные операции.
